# Istochnik

Микросервис генерации тестовых табличных данных. По описанию колонок в JSON возвращает готовый файл в формате CSV, XLSX или SQL.

Сервис не хранит состояние и не использует базу данных: каждый запрос самодостаточен, а результат можно воспроизвести, передав `seed`.

## Возможности

- Шесть стратегий генерации: константа, алгоритм, словарь, регулярное выражение, faker, выражение.
- Вычисляемые колонки: значение считается выражением по другим колонкам той же строки (`total = price * qty`). Стратегия отключается настройкой.
- Базовые типы (`int`, `double`, `str`, `bool`) и пользовательские: даты и время, UUID, точные десятичные числа, часовые пояса, российские реквизиты (СНИЛС, ИНН, КПП, ОГРН, ОГРНИП, ОКПО, БИК, расчётный счёт), IMEI, номера банковских карт («Мир», Visa, Mastercard).
- Случайные значения или последовательности с шагом, ограничения `unique` и `notNull`.
- Распределения случайных чисел и дат: равномерное, нормальное, экспоненциальное и Ципфа.
- Конвертеры — цепочка преобразований над сгенерированной колонкой (арифметика, работа со строками, форматирование дат, хеширование, сортировка).
- Выгрузка в CSV, XLSX и SQL (`INSERT` пачками).
- Конвертация схем: по SQL-миграции или журналу изменений Liquibase строятся готовые запросы на генерацию. Метод отключается настройкой.
- Воспроизводимая генерация по `seed` всего запроса или отдельной колонки.
- Приём запросов на генерацию из очереди RabbitMQ. Включается настройкой.
- Метрики в формате Prometheus. Включаются настройкой.
- Описания типов, стратегий и топиков на русском и английском языках.

## Требования

- JDK 21.
- Maven не нужен: в репозитории есть Maven Wrapper (`mvnw`, `mvnw.cmd`).
- Библиотека `ru.akvine:compozit-commons:1.0-SNAPSHOT` в локальном Maven-репозитории. Она содержит DTO запросов и общие утилиты. Установить её можно командой `mvn install` в репозитории `compozit-commons`.

## Сборка и запуск

Сборка (вместе с тестами):

```bash
./mvnw clean package
```

Готовый jar появится в `target/istochnik-0.0.1-SNAPSHOT.jar`.

У трёх настроек нет значений по умолчанию, без них приложение не стартует:

| Переменная окружения | Назначение |
|---|---|
| `SERVER_PORT` | Порт HTTP-сервера |
| `EUREKA_ENABLED` | Регистрация в Eureka: `true` или `false` |
| `SECURITY_ENABLED` | Проверка JWT на входящих запросах: `true` или `false` |

`EUREKA_URL` (адрес Eureka, например `http://localhost:8700/eureka/`) нужен только при `EUREKA_ENABLED=true`.

Запуск в bash:

```bash
SERVER_PORT=8103 EUREKA_ENABLED=false SECURITY_ENABLED=false java -jar target/istochnik-0.0.1-SNAPSHOT.jar
```

Запуск в PowerShell:

```powershell
$env:SERVER_PORT = "8103"; $env:EUREKA_ENABLED = "false"; $env:SECURITY_ENABLED = "false"
java -jar target\istochnik-0.0.1-SNAPSHOT.jar
```

Для локальной разработки удобно создать файл `src/main/resources/application-local.properties` со своими значениями и запускать приложение с профилем `local` (`--spring.profiles.active=local`). Файлы `application-*.properties` добавлены в `.gitignore`.

## Подключаемые функции

Три функции включаются каждая своей настройкой. Выключенная функция ничего не делает: сервис не подключается к брокеру, не собирает метрики и не открывает дополнительных адресов.

| Функция | Свойство | Переменная окружения | По умолчанию | Что включает |
|---|---|---|---|---|
| OAuth 2.0 | `security.enabled` | `SECURITY_ENABLED` | нет, значение обязательно | Проверку JWT на всех HTTP-запросах — см. [Безопасность](#безопасность) |
| RabbitMQ | `rabbitmq.enabled` | `RABBITMQ_ENABLED` | `false` | Приём запросов на генерацию из очереди — см. [Генерация через RabbitMQ](#генерация-через-rabbitmq) |
| Метрики | `metrics.enabled` | `METRICS_ENABLED` | `false` | Сбор метрик и адрес `/actuator/prometheus` — см. [Метрики](#метрики) |

Функции не зависят друг от друга и включаются в любом сочетании. Запуск со всеми тремя:

```bash
SERVER_PORT=8103 EUREKA_ENABLED=false \
SECURITY_ENABLED=true SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI=https://auth.example.com/realms/demo \
RABBITMQ_ENABLED=true RABBITMQ_HOST=localhost \
METRICS_ENABLED=true \
java -jar target/istochnik-0.0.1-SNAPSHOT.jar
```

## Настройки

Задаются в `src/main/resources/application.properties` или любым способом, который поддерживает Spring Boot.

| Свойство | По умолчанию | Описание |
|---|---|---|
| `max.generation.rows.size` | `100000` | Максимальное число строк в одном запросе |
| `max.generation.columns.size` | `200` | Максимальное число колонок в одном запросе |
| `max.generation.cells.size` | `5000000` | Максимальное число ячеек в одном запросе — строк, умноженных на колонки. Таблица и файл целиком находятся в памяти: запросу из 5 млн ячеек нужно около 1 ГБ кучи. Если куча меньше, уменьшите значение. Лимит общий для всех форматов, хотя ячейка XLSX занимает в памяти примерно в восемь раз больше |
| `max.generation.calculation.enabled` | `false` | Рассчитывать лимиты строк, колонок и ячеек по ресурсам машины при запуске, см. [Расчёт лимитов по ресурсам машины](#расчёт-лимитов-по-ресурсам-машины). При `false` действуют три значения выше |
| `max.generation.calculation.memory-share` | `0.7` | Доля кучи, которую расчёт отдаёт под генерацию: больше 0 и не больше 1 |
| `max.generation.calculation.bytes-per-cell` | `300` | Сколько байт кучи расчёт закладывает на ячейку CSV и SQL |
| `max.generation.calculation.xlsx-bytes-per-cell` | `3000` | Сколько байт кучи расчёт закладывает на ячейку XLSX |
| `max.generation.calculation.users` | `1` | Сколько пользователей могут одновременно отправить запрос предельного размера: память и пул потоков делятся между ними поровну |
| `max.generation.attempts` | `100` | Сколько попыток в среднем на строку есть у случайного генератора, чтобы выполнить ограничения (`unique`, `valid`). При превышении генерация колонки завершается ошибкой |
| `max.dictionaries.per.column` | `10` | Максимальное число словарей в одной колонке |
| `max.dictionary.elements.count` | `10000` | Максимальное число элементов в одном словаре |
| `max.faker.text.length` | `1000` | Максимальная длина текста топика `TEXT` стратегии `faker` |
| `randomizer.seed` | пусто | Глобальный seed. Если задан, имеет приоритет над `seed` запроса и колонок: все запросы становятся детерминированными |
| `sql.insert.batch.size` | `1000` | Максимальное число строк в одном `INSERT`. Значение `0` или меньше отключает разбиение |
| `generation.rate.limiter.enabled` | `true` | Ограничивать частоту запросов на генерацию для каждого пользователя |
| `generation.rate.limiter.limit-for-period` | `20` | Сколько запросов на генерацию принимается от одного пользователя за один период |
| `generation.rate.limiter.refresh-period-seconds` | `1` | Длительность периода в секундах |
| `generation.rate.limiter.max-users` | `10000` | Скольких пользователей ограничитель отслеживает одновременно, см. [Ограничение частоты запросов](#ограничение-частоты-запросов) |
| `generation.expression.enabled` | `true` | Разрешить стратегию `expression` — [вычисляемые колонки](#вычисляемые-колонки) |
| `generation.expression.max-length` | `1000` | Максимальная длина выражения в символах |
| `generation.expression.max-result-length` | `1000` | Максимальная длина строки, которую выражение может вернуть для одной ячейки |
| `generation.regexp.max-count` | `10` | Максимальное число регулярных выражений в одной колонке стратегии `regexp` |
| `generation.regexp.max-length` | `1000` | Максимальная длина регулярного выражения в символах |
| `generation.regexp.max-result-length` | `1000` | Максимальная длина строки, которую задаёт регулярное выражение, см. [Ограничения выражений](#ограничения-выражений) |
| `generation.regexp.max-automaton-states` | `2000` | Максимальное число состояний автомата, который строится по регулярному выражению. Ограничивает сложность выражения |
| `schema.conversion.enabled` | `true` | Разрешить [конвертацию схем](#конвертация-схем) — метод `POST /v1/schemas/convert` |
| `schema.conversion.max-file-size-kb` | `512` | Максимальный размер файла схемы в килобайтах. Файлы больше 1 МБ отклоняет сам Spring Boot с кодом `413`, поэтому для значения больше `1024` увеличьте и `spring.servlet.multipart.max-file-size` |
| `parallel.executor.threads-count` | `0` | Размер пула потоков. Каждая колонка генерируется отдельной задачей. Значение `0` — по числу ядер процессора |
| `parallel.executor.queue-capacity` | `1000` | Размер очереди задач пула |
| `log.total.generation.data.benchmark.enabled` | `false` | Писать в лог время генерации всего запроса |
| `log.column.generation.data.benchmark.enabled` | `false` | Писать в лог время генерации каждой колонки |
| `rabbitmq.enabled` | `false` | Принимать запросы на [генерацию из очереди RabbitMQ](#генерация-через-rabbitmq) |
| `rabbitmq.generation.request-queue` | `istochnik.generation.requests` | Очередь, из которой сервис читает запросы на генерацию |
| `rabbitmq.generation.response-queue` | `istochnik.generation.responses` | Очередь для ответов на запросы, в которых не указан адрес ответа (`reply-to`) |
| `rabbitmq.generation.max-file-size-kb` | `10240` | Максимальный размер файла в килобайтах, который отправляется ответным сообщением |
| `metrics.enabled` | `false` | Собирать [метрики](#метрики) и отдавать их по адресу `/actuator/prometheus` |

### Расчёт лимитов по ресурсам машины

При `max.generation.calculation.enabled=true` лимиты одного запроса не берутся из настроек, а рассчитываются при запуске — по размеру кучи и пулу потоков генерации. Свойства `max.generation.rows.size`, `max.generation.columns.size` и `max.generation.cells.size` в этом режиме не действуют.

| Лимит | Как рассчитывается |
|---|---|
| Ячейки CSV и SQL | Куча × `memory-share` / `users` / `bytes-per-cell` |
| Ячейки XLSX | Куча × `memory-share` / `users` / `xlsx-bytes-per-cell` |
| Колонки | (Потоки пула + размер очереди пула) / `users`, но не больше лимита ячеек. Каждая колонка — отдельная задача пула, и колонки сверх его вместимости запрос отправить не сможет |
| Строки | Равен лимиту ячеек CSV и SQL: таблица из одной колонки может занять все ячейки |

Что получается с коэффициентами по умолчанию на машине с 12 ядрами:

| Куча (`-Xmx`) | Ячейки CSV и SQL | Ячейки XLSX | Колонки | Строки |
|---|---|---|---|---|
| 512 МБ | 1,25 млн | 125 тыс. | 1012 | 1,25 млн |
| 1 ГБ | 2,5 млн | 250 тыс. | 1012 | 2,5 млн |
| 2 ГБ | 5 млн | 500 тыс. | 1012 | 5 млн |
| 4 ГБ | 10 млн | 1 млн | 1012 | 10 млн |

Рассчитанные значения сервис пишет в лог при запуске: строка начинается с `Generation limits are calculated by machine resources`.

Что нужно учитывать:

- Расчёт опирается на размер кучи, а не на память машины. Если `-Xmx` не задан, JVM берёт четверть памяти машины или контейнера, поэтому задайте его явно, например `-Xmx2g` или `-XX:MaxRAMPercentage=75`.
- Коэффициенты подобраны по замерам с запасом примерно в два раза: при куче 1 ГБ запрос из 4–6 млн ячеек `uuid` в CSV и SQL и из 0,6 млн ячеек в XLSX ещё укладывается в память, а лимиты разрешают 2,5 млн и 250 тыс. Если в таблицах много длинных строк — текстов, адресов, — увеличьте `bytes-per-cell` и `xlsx-bytes-per-cell`.
- Лимиты рассчитаны на один запрос предельного размера. Если такие запросы могут прийти одновременно от нескольких пользователей, укажите их число в `users`.
- В XLSX, кроме того, не больше 1 048 575 строк и 16 384 колонок — столько вмещает лист Excel вместе со строкой заголовка.

## API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/v1/generator` | Сгенерировать файл |
| `POST` | `/v1/schemas/convert` | Построить запросы на генерацию по SQL-скрипту или журналу изменений Liquibase |
| `GET` | `/v1/types/base` | Базовые типы |
| `GET` | `/v1/types/custom` | Пользовательские типы с базовым типом и примером значения |
| `GET` | `/v1/strategies` | Стратегии генерации и поддерживаемые ими ограничения |
| `GET` | `/v1/converters` | Конвертеры, доступные для каждого базового типа |
| `GET` | `/v1/topics` | Топики стратегии `faker` с примерами |

Справочные методы (кроме `/v1/converters`) принимают параметр `lang` — язык описаний: `en` (по умолчанию) или `ru`.

### Swagger

Описание всех методов с примерами запросов доступно в Swagger UI запущенного сервиса:

| Адрес | Что там |
|---|---|
| `/swagger-ui.html` | Swagger UI |
| `/v3/api-docs` | Спецификация OpenAPI в формате JSON |

Например, при запуске на порту 8103: `http://localhost:8103/swagger-ui.html`.

При `SECURITY_ENABLED=true` оба адреса, как и остальные методы, требуют JWT. Отключить их совсем можно стандартными свойствами springdoc: `springdoc.swagger-ui.enabled=false` и `springdoc.api-docs.enabled=false`.

### Ограничение частоты запросов

Метод `POST /v1/generator` защищён ограничителем частоты запросов, и лимит у каждого пользователя свой: за период `generation.rate.limiter.refresh-period-seconds` от одного пользователя принимается не больше `generation.rate.limiter.limit-for-period` запросов. Запрос сверх лимита сразу отклоняется с кодом `429`, заголовок `Retry-After` содержит время ожидания в секундах. Исчерпанный лимит одного пользователя не мешает остальным.

| Режим | Кто считается пользователем |
|---|---|
| `SECURITY_ENABLED=true` | Субъект JWT (`sub`): запросы с токенами одного субъекта делят один лимит, с каких бы адресов они ни приходили |
| `SECURITY_ENABLED=false` | Адрес клиента |

Если сервис работает за прокси или шлюзом, у всех запросов один адрес — адрес прокси, и без аутентификации лимит снова становится общим. Чтобы сервис брал адрес клиента из заголовка `X-Forwarded-For`, включите `server.forward-headers-strategy=native`. Заголовок принимается только от адресов из `server.tomcat.remoteip.internal-proxies` — по умолчанию это внутренние сети. Если клиенты обращаются к сервису напрямую из тех же сетей, они могут подставить в заголовок любой адрес: тогда сузьте это свойство до адресов прокси.

Ограничитель пользователя хранится в памяти, пока тот присылает запросы, и удаляется, когда запросов не было дольше периода. Одновременно отслеживается не больше `generation.rate.limiter.max-users` пользователей: если их больше, ограничители самых редких пользователей сбрасываются, и те получают лимит заново.

Лимиты считаются отдельно в каждом экземпляре приложения. На справочные методы и на запросы из очереди RabbitMQ ограничитель не распространяется.

## Запрос на генерацию

`POST /v1/generator`

Параметр строки запроса `tableName` задаёт имя возвращаемого файла (по умолчанию `response`).

Пример тела запроса:

```json
{
  "size": 3,
  "fileType": "sql",
  "tableName": "users",
  "columns": [
    {
      "name": "id",
      "type": "int",
      "generationStrategy": "algorithm",
      "config": { "rangeType": "shift", "start": "1", "step": "1" }
    },
    {
      "name": "full_name",
      "type": "str",
      "generationStrategy": "faker",
      "config": { "rangeType": "random", "notNull": true, "language": "ru", "topics": ["FULL_NAME"] }
    },
    {
      "name": "status",
      "type": "str",
      "generationStrategy": "dictionary",
      "config": { "rangeType": "random", "notNull": true, "dictionaries": [["NEW", "ACTIVE", "BLOCKED"]] }
    },
    {
      "name": "balance",
      "type": "decimal",
      "generationStrategy": "algorithm",
      "config": { "rangeType": "random", "notNull": true, "start": "0.00", "end": "10000.00" }
    },
    {
      "name": "created_at",
      "type": "datetime",
      "generationStrategy": "algorithm",
      "config": { "rangeType": "random", "notNull": true, "start": "2025-01-01 00:00:00", "end": "2025-12-31 23:59:59" },
      "converters": [{ "name": "format", "arguments": ["yyyy-MM-dd HH:mm:ss"] }]
    }
  ]
}
```

Вызов:

```bash
curl -X POST "http://localhost:8103/v1/generator?tableName=users_dump" -H "Content-Type: application/json" -d @request.json -o users_dump.sql
```

Ответ — файл `users_dump.sql`:

```sql
INSERT INTO users (ID, FULL_NAME, STATUS, BALANCE, CREATED_AT) VALUES
(1, 'Киселев Артём', 'ACTIVE', '6368.57', '2025-05-24 02:57:38'),
(2, 'Валентина Сергеевна Кудрявцева', 'BLOCKED', '622.51', '2025-02-16 14:22:46'),
(3, 'Константин Кулагин', 'NEW', '1462.85', '2025-09-27 22:59:18');
```

Больше готовых запросов — в папке [samples](samples/README.md): по одному на каждый тип, на каждую стратегию, на конвертеры и на таблицы целиком.

### Поля запроса

| Поле | Описание |
|---|---|
| `size` | Количество строк |
| `fileType` | Формат файла: `csv`, `xlsx` или `sql` |
| `tableName` | Имя таблицы в `INSERT`. Обязательно для `sql` |
| `seed` | Seed всего запроса: при том же seed и тех же параметрах файл получается тем же, см. [Воспроизводимость](#воспроизводимость) |
| `columns` | Список колонок. Порядок колонок в файле совпадает с порядком в запросе |

### Воспроизводимость

По умолчанию каждый запрос даёт новые значения. Чтобы получить тот же файл ещё раз, передайте `seed` — для всего запроса или для отдельных колонок:

```json
{
  "size": 1000,
  "fileType": "csv",
  "seed": "orders-2025",
  "columns": [ ... ]
}
```

При том же `seed` и тех же параметрах запрос возвращает тот же файл.

- Из `seed` запроса каждая колонка получает свой seed по имени. Поэтому колонки с одинаковыми настройками не повторяют друг друга, а значения колонки не меняются, если в запросе переставить колонки или добавить новые. Колонки с одинаковыми именами тоже получают разные значения.
- `seed` колонки важнее `seed` запроса: такая колонка не зависит от `seed` запроса.
- Глобальный seed из настройки `randomizer.seed` важнее обоих.
- Пустой `seed` — то же, что его отсутствие.

### Поля колонки

| Поле | Описание |
|---|---|
| `name` | Имя колонки |
| `generationStrategy` | Стратегия: `constant`, `algorithm`, `dictionary`, `regexp`, `faker`, `expression` |
| `type` | Тип данных. Для `algorithm` — тип генерируемых значений, для `expression` — базовый тип результата; для остальных стратегий укажите `str` |
| `config` | Параметры генерации (обязательный объект, см. ниже) |
| `converters` | Конвертеры, применяются к сгенерированным значениям по порядку |
| `convertToString`, `postConverters` | Если `convertToString=true`, значения нестрокового типа стратегии `algorithm` переводятся в строки, после чего к ним применяются строковые конвертеры из `postConverters` |
| `errorResolveInfo` | Что делать при ошибке генерации колонки: `{"policy": "INTERRUPT"}` — прервать запрос (по умолчанию), `{"policy": "IGNORE", "defaultValue": "..."}` — заполнить колонку значением `defaultValue` |

| Поле | Описание |
|---|---|

| `start`, `end`, `step` | Границы диапазона и шаг. Передаются строками, формат зависит от типа |

| `length` | Длина строки для типа `str` и длина текста для топика `TEXT` стратегии `faker` |

| `dictionaries` | Словари для стратегии `dictionary` |

| `seed` | Seed колонки. Одинаковый seed при одинаковых параметрах даёт одинаковые значения. Важнее seed запроса |

## Стратегии генерации

| Стратегия | Что делает | Параметры `config` |
|---|---|---|
| `constant` | Заполняет колонку одним значением | `constant` |
| `algorithm` | Генерирует значения указанного типа | Зависят от типа, см. [Типы данных](#типы-данных) |
| `dictionary` | Выбирает значения из словарей. `random` — случайно, `shift` — по порядку по кругу. Одинаковые элементы разных словарей считаются одним значением | `dictionaries`, `rangeType`, `notNull`, `unique`, `weights` |
| `regexp` | Генерирует строки, подходящие под регулярные выражения. `random` — выражение выбирается случайно, `shift` — по очереди. Поддерживается подмножество синтаксиса регулярных выражений (библиотека Xeger) | `regexps`, `rangeType`, `notNull` |
| `faker` | Генерирует правдоподобные данные по темам: имена, адреса, телефоны, email, текст, координаты и другие. Полный список — в `GET /v1/topics` | `topics`, `language`, `rangeType`, `notNull`; для топика `TEXT` — `length` |
| `expression` | Вычисляет значение по другим колонкам той же строки, см. [Вычисляемые колонки](#вычисляемые-колонки) | `expression`, `notNull` |

Строковые конвертеры доступны для стратегий `dictionary`, `regexp` и `faker`. Для `expression` доступны конвертеры типа колонки — см. [Конвертеры вычисляемых колонок](#конвертеры-вычисляемых-колонок). Для `constant` конвертеры не применяются.

В регулярных выражениях стратегии `regexp` символы `@`, `#`, `&`, `~`, `<`, `>` и `"` имеют особое значение. Чтобы получить сам символ, экранируйте его обратной косой чертой: `[a-z]{5}\@example\.com` (в JSON — `"[a-z]{5}\\@example\\.com"`).

### Плюсы и минусы стратегий

| Стратегия | `unique` | `notNull` | Конвертеры | Проверка параметров до генерации | Значения в файле |
|---|---|---|---|---|---|
| `constant` | — | — | нет | нет | как в запросе: строка, число или логическое значение |
| `algorithm` | да | да | по базовому типу | да, для большинства типов | по базовому типу: числа, логические значения или строки |
| `dictionary` | да | да | строковые | да | строки |
| `regexp` | нет | да | строковые | да | строки |
| `faker` | нет | да | строковые | топики и длина текста | строки |
| `expression` | нет | да | по типу колонки | да | по типу колонки: числа, логические значения или строки |

#### `constant`

Подходит для колонок с одним значением на всю таблицу: код валюты, признак, версия.

Плюсы:

- Самая простая и самая быстрая стратегия: нужно одно поле `constant`.
- Результат полностью предсказуем.
- Тип значения сохраняется: число остаётся числом и попадает в SQL без кавычек.

Минусы:

- Одно значение на всю колонку, `unique` и `notNull` не применяются.
- Конвертеры игнорируются.
- Поддерживаются только строки, числа и логические значения. Объект или массив в `constant` приводит к ошибке при выгрузке в SQL и XLSX.

#### `algorithm`

Подходит для идентификаторов, чисел, дат и реквизитов — всего, где важны диапазон, порядок или корректность контрольного разряда.

Плюсы:

- Самый широкий набор возможностей: 31 тип, включая даты с часовым поясом, точные десятичные числа, реквизиты и номера карт.
- Точное управление значениями: диапазон, шаг, последовательности, `unique`, `notNull`, корректные контрольные разряды через `valid`.
- Для чисел и дат задаётся [распределение](#распределения-значений): нормальное, экспоненциальное или Ципфа.
- Числа и логические значения остаются типизированными, для них доступны числовые конвертеры.
- Параметры большинства типов проверяются до генерации: ошибка возвращается с кодом `400` и описанием по каждой колонке.

Минусы:

- Только предусмотренные типы: произвольный формат строки так не получить.
- У каждого типа свои параметры и свой формат `start` и `end`, без таблицы типов не обойтись.
- Нет правдоподобных имён и адресов, а перекосы, характерные для реальных данных, задаются только для чисел и дат.

#### `dictionary`

Подходит для справочных значений: статусы, категории, города, коды.

Плюсы:

- В колонке окажутся в точности те значения, которые нужны.
- Поддерживает `unique` и `notNull`, случайный выбор и обход по порядку.
- Частоту значений можно задать весами: статус `NEW` в 70 % строк, `BLOCKED` в 5 %.
- Нехватка значений для `unique` обнаруживается до генерации (код `400`).
- Одна из самых быстрых стратегий.

Минусы:

- Все значения нужно передать в запросе, и на них есть лимиты: по умолчанию 10 словарей по 10 000 элементов на колонку.
- Разнообразие ограничено размером словаря: уникальных строк не больше, чем элементов.
- Значения всегда строки: числа из словаря попадут в SQL в кавычках.
- Веса работают только со случайным выбором: с `shift` и с `unique` их задать нельзя.

##### Веса значений словаря

По умолчанию все значения словарей равновероятны. Поле `weights` задаёт значениям веса: значение выбирается тем чаще, чем больше его вес.

```json
{
  "name": "status",
  "type": "str",
  "generationStrategy": "dictionary",
  "config": {
    "rangeType": "random",
    "notNull": true,
    "dictionaries": [["NEW", "ACTIVE", "BLOCKED"]],
    "weights": { "NEW": 70, "ACTIVE": 25, "BLOCKED": 5 }
  }
}
```

Доля значения — его вес, делённый на сумму весов: здесь `NEW` попадёт примерно в 70 % строк, `ACTIVE` — в 25 %, `BLOCKED` — в 5 %. Веса не обязаны давать в сумме 100.

- Значения, которых нет в `weights`, получают вес 1. Например, при словаре из 50 городов и `"weights": { "Москва": 21 }` на Москву придётся 30 % строк, на остальные 49 городов — поровну.
- Вес 0 исключает значение. Вес может быть дробным, но не отрицательным.
- Значение из нескольких словарей — одно значение и с одним весом.
- В колонке с `notNull: false` примерно половина значений по-прежнему `null`, а веса распределяют остальные.
- Значения в `weights`, которых нет в словарях, веса с `shift` или с `unique` — ошибки проверки запроса с кодом `400`.
- Запрос без `weights` работает как раньше: при том же `seed` получаются те же значения.

#### `regexp`

Подходит для строк собственного формата, которого нет среди типов: номера заказов, артикулы, маски телефонов.

Плюсы:

- Любой формат строки без доработки сервиса.
- Несколько выражений в одной колонке: случайный выбор или чередование.
- Доступны строковые конвертеры.

Минусы:

- Нет `unique`: повторы возможны.
- Длина и сложность выражений ограничены, см. [Ограничения выражений](#ограничения-выражений). Сильнее всего это заметно на выражениях, где повтор без верхней границы стоит перед повтором тех же символов: `[ab]*a[ab]{10}` уже не пройдёт проверку.
- Синтаксис отличается от привычного. Классы `\d` и `\w` не работают — нужны `[0-9]` и `[a-z]`. Точка даёт произвольные символы Юникода. Часть символов служебные (см. выше).
- Квантификаторы без верхней границы (`*`, `+`) дают строки непредсказуемой длины — лучше указывать её явно: `{6}`, `{2,5}`.
- Не умеет считать контрольные разряды, и это одна из самых медленных стратегий.

##### Ограничения выражений

Выражения проверяются до генерации: синтаксическая ошибка или нарушение ограничения возвращается с кодом `400` и описанием по колонке.

| Ограничение | Настройка | По умолчанию |
|---|---|---|
| Выражений в одной колонке | `generation.regexp.max-count` | 10 |
| Длина выражения | `generation.regexp.max-length` | 1000 символов |
| Длина строки, которую задаёт выражение | `generation.regexp.max-result-length` | 1000 символов |
| Сложность выражения | `generation.regexp.max-automaton-states` | 2000 состояний автомата |

Длина строки считается по самому длинному варианту: у `[a-z]{3,8}` это 8 символов, у `(a{100}){100}` — 10 000. Повтор без верхней границы считается одним повтором, а `{n,}` — n повторами: сколько их будет на самом деле, решает случай.

Сложность ограничена потому, что генератор строит по выражению детерминированный автомат, а у некоторых коротких выражений он огромен. `[ab]*a[ab]{20}` требует двух миллионов состояний: раньше такое выражение исчерпывало память, теперь отклоняется проверкой. Номера, коды и маски укладываются в десятки состояний, а наибольшее допустимое по длине выражение `[a-z]{1000}` — в 1001.

#### `faker`

Подходит для правдоподобных, читаемых данных: ФИО, адреса, телефоны, email, описания.

Плюсы:

- Данные выглядят как настоящие — удобно для демонстраций и ручного тестирования.
- Локализация через `language`: русские или английские имена и адреса.
- Несколько топиков в одной колонке, доступны строковые конвертеры.

Минусы:

- Нет `unique`: значения повторяются, особенно имена.
- Нет параметров диапазона (кроме длины текста у топика `TEXT`), набор топиков фиксирован (список — в `GET /v1/topics`).
- Колонки не связаны между собой: имя в одной колонке и email в другой не соответствуют друг другу. Связать значения можно стратегией `expression`.
- Составные топики (например, полный адрес) генерируются в несколько раз медленнее чисел и словарей.

Особенности отдельных топиков:

- `TEXT` — текст-заполнитель (lorem ipsum) ровно заданной длины: `"topics": ["TEXT"], "length": 250`. Без `length` длина равна 100 символам, наибольшую задаёт настройка `max.faker.text.length`. Язык колонки на текст не влияет. Если в колонке несколько топиков, длина относится только к тексту.
- `COORDINATES` — координаты точки: широта (от -90 до 90) и долгота (от -180 до 180) через запятую, в градусах с шестью знаками после запятой: `55.751244, 37.618423`. Дробная часть отделяется точкой при любом языке. Точки распределены по земному шару равномерно, поэтому чаще попадают в океан, чем на сушу.

#### `expression`

Подходит для колонок, которые должны согласовываться с другими колонками строки: сумма по цене и количеству, email по имени и фамилии, дата окончания позже даты начала.

Плюсы:

- Единственная стратегия, которая связывает колонки между собой.
- Арифметика, строки, условия, сравнения и сдвиг дат в одном выражении; к результату применяются конвертеры.
- Порядок вычисления определяется по ссылкам между колонками, порядок колонок в запросе не важен.
- Выражение, ссылки на колонки и циклы проверяются до генерации (код `400`).
- Числа и логические значения остаются типизированными и попадают в SQL без кавычек.

Минусы:

- Сама случайных значений не создаёт: разнообразие берётся из исходных колонок.
- Нет `unique`.
- Тип результата — только базовый: даты и точные десятичные числа записываются строками.
- Ошибки в данных (деление на ноль, строка вместо числа) обнаруживаются только во время генерации и возвращаются с кодом `500`.
- Ссылаться можно только на колонки той же строки: значений из соседних строк и итогов по колонке нет.

По скорости стратегии различаются в разы: быстрее всех `constant` и `dictionary`, медленнее всех `regexp` и составные топики `faker`. Но и самые медленные генерируют колонку из 100 000 строк меньше чем за секунду. Вычисляемая колонка из 100 000 строк тоже считается за доли секунды.

## Вычисляемые колонки

Стратегия `expression` считает значение колонки по другим колонкам той же строки. Выражение задаётся в поле `config.expression`, тип результата — в поле `type` колонки.

```json
{
  "size": 3,
  "fileType": "csv",
  "columns": [
    {
      "name": "price",
      "type": "decimal",
      "generationStrategy": "algorithm",
      "config": { "rangeType": "random", "notNull": true, "start": "1.00", "end": "500.00" }
    },
    {
      "name": "qty",
      "type": "int",
      "generationStrategy": "algorithm",
      "config": { "rangeType": "random", "notNull": true, "start": "1", "end": "10" }
    },
    {
      "name": "total",
      "type": "str",
      "generationStrategy": "expression",
      "config": { "expression": "#price * #qty" }
    },
    {
      "name": "is_large",
      "type": "bool",
      "generationStrategy": "expression",
      "config": { "expression": "#toDouble(#total) > 1000" }
    }
  ]
}
```

Ответ:

```csv
price;qty;total;is_large
29.30;3;87.90;false
272.50;9;2452.50;true
206.94;4;827.76;false
```

Больше примеров — в [samples/strategies/expression.json](samples/strategies/expression.json) и [samples/tables/orders.json](samples/tables/orders.json).

### Порядок вычисления

Вычисляемая колонка может ссылаться на обычные колонки и на другие вычисляемые. Порядок колонок в запросе не важен: сервис определяет порядок вычисления по ссылкам. Сначала одновременно генерируются обычные колонки, затем вычисляемые: колонки, которые не зависят друг от друга, считаются одновременно, зависимые — после тех, на которые они ссылаются.

Ссылка на неизвестную колонку, на саму себя и цикл из ссылок (`a` ссылается на `b`, а `b` на `a`) — ошибки проверки запроса с кодом `400`.

### Ссылки на колонки

| Запись | Когда подходит |
|---|---|
| `#имя` | Имя колонки состоит из букв (в том числе кириллицы), цифр и `_` и не начинается с цифры: `#price`, `#first_name`, `#цена` |
| `#row['имя']` | Любое имя: с пробелами, дефисами, с цифрой в начале или совпадающее с именем функции — `#row['Дата заказа']`, `#row['lower']` |

Имя колонки, на которую ссылается выражение, должно встречаться в запросе один раз.

### Что можно писать в выражении

Выражения пишутся на подмножестве [Spring Expression Language](https://docs.spring.io/spring-framework/reference/core/expressions.html):

| Конструкция | Запись |
|---|---|
| Литералы | `42`, `3.14`, `'текст'`, `true`, `null` |
| Арифметика | `+`, `-`, `*`, `/`, `%`. Деление целых чисел даёт целое: `7 / 2` равно `3`, а `7 / 2.0` равно `3.5` |
| Склейка строк | `#last_name + ' ' + #first_name`, `'ORD-' + #id` |
| Сравнение | `==`, `!=`, `<`, `<=`, `>`, `>=`, `#qty between {1, 10}` |
| Логика | `and`, `or`, `!` |
| Условие | `#qty >= 10 ? 'опт' : 'розница'` |
| Замена `null` | `#middle_name ?: ''` — значение или замена, если оно `null` |
| Функции | `#lower(#name)`, список ниже |

Остальные возможности языка отклоняются при проверке запроса: вызовы методов и обращение к свойствам (`#name.length()`), типы (`T(...)`), конструкторы (`new`), бины (`@...`), присваивание, сопоставление с регулярным выражением (`matches`) и оператор `^` (вместо него есть `#pow`).

Целое число больше 2 147 483 647 записывается с суффиксом `L`: `10000000000L`.

### Условия

Отдельных операторов `if` и `else` в выражениях нет. Условие записывается как `условие ? значение_если_да : значение_если_нет` и само является значением, поэтому его можно использовать в любом месте выражения:

| Задача | Выражение |
|---|---|
| Выбрать одно из двух значений | `#qty >= 10 ? 'опт' : 'розница'` |
| Выбрать одно из нескольких — вложенное условие в скобках | `#qty == 0 ? 'нет' : (#qty < 3 ? 'мало' : 'много')` |
| Изменить часть вычисления | `#round(#price * #qty * (#qty >= 5 ? 0.9 : 1), 2)` |
| Избежать деления на ноль | `#qty > 0 ? #price / #qty : 0` |
| Получить признак — колонка с `"type": "bool"`, выражение целиком является условием | `#qty >= 5 and #toDouble(#total) > 1000` |

Вычисляется только та ветка, которую выбрало условие: в примере с делением при `qty = 0` деление не выполняется.

Значения во всех ветках должны подходить типу колонки. Выражение `#qty > 0 ? #price / #qty : 'n/a'` в колонке `double` завершится ошибкой на первой же строке с `qty = 0`: строку `'n/a'` нельзя привести к числу (см. [Типы значений](#типы-значений)).

### Функции

| Функция | Результат |
|---|---|
| `#lower(s)`, `#upper(s)` | Строка в нижнем, в верхнем регистре |
| `#length(s)` | Длина строки |
| `#substring(s, begin, end)` | Подстрока с позиции `begin` (считая с нуля, включительно) до позиции `end` (не включая). Позиции за границами строки приводятся к границам |
| `#abs(x)` | Модуль числа |
| `#round(x, scale)` | Округление до `scale` знаков после запятой; половина округляется вверх |
| `#min(a, b)`, `#max(a, b)` | Меньшее, большее из двух чисел |
| `#pow(x, y)` | Возведение в степень, результат — дробное число |
| `#toInt(v)` | Целое из числа или строки с числом; дробная часть округляется до ближайшего целого |
| `#toDouble(v)` | Дробное число из числа или строки с числом |
| `#toStr(v)` | Строка из любого значения; числа записываются без экспоненты |
| `#plusDays(d, n)`, `#plusMonths(d, n)`, `#plusYears(d, n)` | Сдвиг даты (`2025-12-25`) или даты и времени (`2025-12-25T10:30:00`) на `n` дней, месяцев, лет. Отрицательное `n` сдвигает назад |
| `#daysBetween(from, to)` | Количество дней от даты `from` до даты `to`; отрицательное, если `to` раньше |

Если любой аргумент функции равен `null`, её результат тоже `null`.

### Типы значений

Какой тип имеет значение колонки в выражении:

| Колонка | Значение в выражении |
|---|---|
| `int` и пользовательские типы на его основе (`snils`, `inn_org`, `inn_pers`, `ogrn`) | Целое число |
| `double` | Дробное число |
| `bool` | Логическое значение |
| `decimal` | Точное десятичное число: `#price * #qty` считается без потери точности |
| Остальные типы `algorithm` (строки, даты, реквизиты), стратегии `dictionary`, `regexp`, `faker` | Строка |
| `constant` | Как в запросе: строка, число или логическое значение |
| `expression` | По полю `type` колонки |

Строка с числом сама числом не становится: для арифметики её нужно преобразовать — `#toDouble(#total) * 2`. Умножение строки на число считается ошибкой.

Даты и время в выражении — строки в формате ISO (`2025-12-25`, `2025-12-25T10:30:00`). Их можно сравнивать между собой и сдвигать функциями. Если к исходной колонке применён конвертер `format`, функции дат её значения не разберут: применяйте `format` к вычисляемой колонке.

Результат выражения приводится к типу колонки:

| `type` | Что принимается |
|---|---|
| `int` | Число или строка с числом; дробная часть округляется до ближайшего целого |
| `double` | Число или строка с числом |
| `str` | Любое значение; числа записываются без экспоненты, у точных десятичных чисел сохраняется количество знаков после запятой |
| `bool` | Логическое значение или строка `true` / `false` |

Тип значений колонки задаёт поле `type`, а не выражение. Если выражение вернуло значение другого типа, оно приводится к типу колонки по таблице выше: в колонке `double` строка `'12.5'` станет числом `12.5`.

Если результат привести нельзя — например, в колонке `double` выражение вернуло `'n/a'`, — генерация колонки завершается ошибкой `result [n/a] can't be converted to type [double]`. Для этого достаточно одной такой строки. Проверка запроса эту ошибку не находит: тип результата становится известен только во время вычисления. Что происходит с запросом дальше, зависит от `errorResolveInfo` колонки — см. «Ограничения» ниже.

### Конвертеры вычисляемых колонок

К вычисляемой колонке применяются конвертеры из поля `converters`. Порядок такой: выражение вычисляется для всех строк, результат приводится к типу колонки, и только после этого работают конвертеры. Поэтому набор конвертеров зависит от поля `type`, а не от того, что вернуло выражение:

| `type` | Доступные [конвертеры](#конвертеры) |
|---|---|
| `int` | Для `int` и общие |
| `double` | Для `double` и общие |
| `str` | Для `str` и общие |
| `bool` | Конвертеров нет: запрос с ними отклоняется с кодом `400` |

Одно и то же выражение с разным `type` принимает разные конвертеры:

```json
{
  "name": "total",
  "type": "double",
  "generationStrategy": "expression",
  "config": { "expression": "#price * #qty" },
  "converters": [{ "name": "round", "arguments": [1] }]
},
{
  "name": "total_label",
  "type": "str",
  "generationStrategy": "expression",
  "config": { "expression": "#price * #qty" },
  "converters": [{ "name": "addAfter", "arguments": [" RUB"] }]
}
```

- Конвертер, который типу колонки не подходит (например, `upperCase` в колонке `int`), применить нельзя: запрос завершится ошибкой.
- Поля `convertToString` и `postConverters` на вычисляемые колонки не действуют. Чтобы обработать число строковым конвертером, задайте колонке `"type": "str"` или добавьте вторую вычисляемую колонку типа `str`, которая ссылается на числовую.
- Колонки, которые ссылаются на вычисляемую, получают её значения уже после конвертеров.
- Если в колонке могут быть `null`, проверьте, что её конвертеры это допускают: `round` и другие конвертеры `double` на значении `null` завершают генерацию колонки ошибкой. Для такой колонки возвращайте число во всех ветках условия и обрабатывайте `null` исходных колонок в самом выражении.

### `null` в исходных колонках

Поведение зависит от поля `notNull` вычисляемой колонки:

- `notNull: false` (по умолчанию) — как в SQL: если в строке хотя бы одна из колонок, на которые ссылается выражение, равна `null`, результат тоже `null`, а выражение для этой строки не вычисляется.
- `notNull: true` — выражение вычисляется для каждой строки и получает `null` как есть. Обработать его можно условием или оператором `?:`, например `#last_name + (#middle_name == null ? '' : ' ' + #middle_name)`. Если результат всё равно оказался `null`, генерация колонки завершается ошибкой.

### Ограничения

- `unique` и `valid` не поддерживаются.
- Тип колонки — только базовый: `int`, `double`, `str` или `bool`.
- Длина выражения и длина строки-результата ограничены настройками `generation.expression.max-length` и `generation.expression.max-result-length`.
- Ошибка вычисления хотя бы в одной строке (деление на ноль, неподходящий тип) останавливает генерацию колонки. Дальше действует политика из `errorResolveInfo`: запрос прерывается с кодом `500` или колонка заполняется значением по умолчанию. Зависимые колонки в этом случае считаются по значению по умолчанию.

### Отключение стратегии

Настройка `generation.expression.enabled=false` отключает вычисляемые колонки. Запрос с колонкой `expression` отклоняется с кодом `400`, `GET /v1/strategies` стратегию не возвращает, остальные стратегии работают как прежде.

## Распределения значений

По умолчанию случайные значения распределены по диапазону равномерно. Для чисел, дат и времени другое распределение задаётся в поле `config.distribution`:

```json
{
  "name": "age",
  "type": "int",
  "generationStrategy": "algorithm",
  "config": {
    "rangeType": "random",
    "notNull": true,
    "start": "18",
    "end": "90",
    "distribution": { "type": "normal", "mean": "35", "stddev": "10" }
  }
}
```

Значения по-прежнему лежат в диапазоне от `start` до `end`: распределение меняет только то, как часто встречается каждое из них.

| `type` | Как распределены значения | Параметры |
|---|---|---|
| `uniform` | Равномерно: все значения диапазона равновероятны. То же, что без `distribution` | — |
| `normal` | «Колокол»: значения собраны вокруг среднего и встречаются тем реже, чем дальше от него | `mean`, `stddev` |
| `exponential` | Чаще всего у одной из границ диапазона, с удалением от неё — всё реже | `stddev`, `peak` |
| `zipf` | Закон Ципфа: значение, k-е по счёту от границы, встречается в k^`exponent` раз реже первого. Несколько значений занимают большую часть строк, остальные образуют длинный хвост | `exponent`, `peak` |

Параметры необязательны:

| Параметр | Значение | По умолчанию |
|---|---|---|
| `mean` | Среднее — центр «колокола». Записывается в том же формате, что `start` и `end`, и лежит между ними | Середина диапазона |
| `stddev` | Стандартное отклонение в единицах шага типа: для чисел — в единицах значения, для `date` — в днях, для `time`, `datetime` и `zoned_datetime` — в секундах. У `normal` в пределах одного отклонения от среднего лежит 68 % значений, в пределах двух — 95 %. У `exponential` это среднее расстояние значения от пика | Для `normal` — шестая часть ширины диапазона, для `exponential` — пятая |
| `exponent` | Показатель степени: больше 0 и не больше 10. Чем он больше, тем сильнее преобладают самые частые значения | `1` |
| `peak` | У какой границы значения встречаются чаще: `start` или `end` | `start` |

Примеры:

| Задача | `distribution` |
|---|---|
| Возраст клиентов около 35 лет | `{ "type": "normal", "mean": "35", "stddev": "10" }` |
| Время визита с пиком в середине дня | `{ "type": "normal", "mean": "13:00:00", "stddev": "5400" }` |
| Сумма покупки: много мелких, мало крупных | `{ "type": "exponential", "stddev": "1500" }` |
| Дата регистрации: свежих больше, чем старых | `{ "type": "exponential", "stddev": "60", "peak": "end" }` |
| Идентификатор клиента в заказах: несколько клиентов делают большую часть заказов | `{ "type": "zipf" }` |

Готовый запрос — [samples/options/distribution.json](samples/options/distribution.json).

Что нужно учитывать:

- Распределения поддерживаются для типов `int`, `double`, `decimal`, `date`, `time`, `datetime` и `zoned_datetime` и только при `rangeType: random`.
- Часть распределения, которая выходит за границы диапазона, отсекается. Например, `normal` со средним на границе даёт половину «колокола».
- `zipf` нумерует отдельные значения типа: для `int` это числа, для `date` — дни, для `datetime` — секунды, для `decimal` — единицы младшего разряда. Для `double` он не поддерживается: у дробных чисел таких значений нет. При `exponent: 1` и диапазоне из тысячи значений на самое частое приходится 13 % строк, на второе — вдвое меньше. Если нужен плавный спад без множества повторов, подойдёт `exponential`.
- С `unique: true` распределение совместимо, но рядом с острым пиком уникальные значения быстро заканчиваются. Если их не хватает на все строки, генерация колонки завершается ошибкой по лимиту попыток (`max.generation.attempts`).
- Параметр, который не относится к выбранному распределению (например, `mean` для `exponential`), считается ошибкой и возвращается с кодом `400`, как и остальные ошибки в описании распределения.
- Без `distribution` и с `"type": "uniform"` значения при одном и том же `seed` остаются такими же, как в предыдущих версиях сервиса.
- Колонка с распределением генерируется в полтора–три раза дольше равномерной.

## Конвертеры

Конвертер описывается объектом:

```json
{ "name": "multiply", "arguments": [1.5], "probability": 50 }
```

- `name` — имя конвертера;
- `arguments` — аргументы, если они нужны;
- `probability` — к какой доле строк (в процентах, от 1 до 100) применить конвертер. По умолчанию 100.

Какие конвертеры доступны, зависит от базового типа колонки.

### Для `int`

| Конвертер | Аргументы | Действие |
|---|---|---|
| `abs` | — | Модуль числа |
| `negative` | — | Смена знака |
| `plus`, `minus` | число | Сложение, вычитание |
| `multiply` | число | Умножение. Дробная часть результата отбрасывается |
| `divide` | число, не 0 | Деление. Дробная часть результата отбрасывается |
| `mod` | число | Остаток от деления |
| `pow` | число | Возведение в степень |
| `factorial` | — | Факториал |

### Для `double`

| Конвертер | Аргументы | Действие |
|---|---|---|
| `abs`, `negative` | — | Модуль числа, смена знака |
| `plus`, `minus`, `multiply` | число | Сложение, вычитание, умножение |
| `divide` | число, не 0 | Деление |
| `pow` | число | Возведение в степень |
| `round` | количество знаков | Округление |
| `ceil`, `floor` | — | Округление вверх, вниз |
| `sin`, `cos`, `tan`, `cot`, `arcsin`, `arccos`, `arctan` | — | Тригонометрические функции |
| `exp` | — | Экспонента |
| `log`, `log10` | число, не 0 (обязателен, в вычислении не участвует) | Натуральный и десятичный логарифм |
| `zscore` | — | Стандартизация значений колонки |
| `minMaxScaling` | — | Приведение значений колонки к диапазону от 0 до 1 |

### Для `str`

| Конвертер | Аргументы | Действие |
|---|---|---|
| `upperCase`, `lowerCase` | — | Верхний, нижний регистр |
| `capitalize` | — | Первая буква в верхнем регистре |
| `inversion` | — | Смена регистра каждой буквы на противоположный |
| `randomCase` | — | Случайная смена регистра букв |
| `trim` | — | Удаление пробелов по краям |
| `removeWhitespaces` | — | Удаление пробельных символов |
| `reverse` | — | Строка в обратном порядке |
| `addBefore`, `addAfter` | текст | Добавление текста в начало, в конец |
| `repeat` | количество (по умолчанию 1) | Повтор строки |
| `padLeft`, `padRight` | длина (от 0 до 1000), символ (по умолчанию пробел) | Дополнение строки слева, справа до заданной длины: `padLeft` с аргументами `[6, "0"]` превращает `42` в `000042`. Строки не короче этой длины не меняются |
| `substring` | начальный и конечный индексы | Подстрока |
| `truncate` | наибольшая длина | Обрезка строки до заданной длины. В отличие от `substring`, строки короче этой длины не приводят к ошибке и не меняются |
| `replaceAll` | регулярное выражение, замена | Замена по регулярному выражению |
| `mask` | сколько символов оставить в начале и в конце (по умолчанию 0 и 0), символ маски (по умолчанию `*`) | Замена середины строки символом маски: с аргументами `[4, 4]` строка `2200123456789019` превращается в `2200********9019`. Строка не длиннее оставляемой части не меняется |
| `format` | шаблон, например `dd.MM.yyyy HH:mm:ss` | Форматирование значений `date`, `datetime` и `zoned_datetime` |
| `translit` | — | Транслитерация кириллицы |
| `base64` | — | Кодирование в Base64 |
| `md5` | — | Хеш MD5 в шестнадцатеричном виде |
| `randomNumericReplace` | — | Замена цифр случайными цифрами |
| `randomEnglishReplace`, `randomRussianReplace` | — | Замена латинских или кириллических букв случайными буквами того же алфавита |
| `randomReplace` | — | Замена каждого символа случайной буквой, цифрой или спецсимволом |

### Общие (для `int`, `double` и `str`)

| Конвертер | Действие |
|---|---|
| `shuffle` | Перемешивание значений колонки |
| `sort_asc`, `sort_desc` | Сортировка по возрастанию, по убыванию |
| `to_null` | Замена значений на `null` с вероятностью `probability` |

Для `bool` конвертеров нет.

## Форматы файлов

- **CSV** — разделитель `;`, первая строка содержит имена колонок, `null` записывается пустым значением.
- **XLSX** — один лист `sheet`, первая строка содержит имена колонок.
- **SQL** — операторы `INSERT INTO ... VALUES`, не более `sql.insert.batch.size` строк в каждом. Имена колонок переводятся в верхний регистр. Строки заключаются в одинарные кавычки, числа и логические значения пишутся без кавычек, `null` — как `NULL`. Имена таблицы и колонок подставляются как есть, без экранирования, поэтому передавайте только проверенные значения.

## Конвертация схем

Если таблицы уже описаны в миграциях приложения, запрос на генерацию не нужно писать вручную. Метод `POST /v1/schemas/convert` принимает файл миграции и для каждой таблицы из него возвращает готовый запрос к `POST /v1/generator`.

```bash
curl -X POST "http://localhost:8103/v1/schemas/convert?size=1000" -F "file=@samples/schemas/V1__shop.sql"
```

Файл передаётся частью `file` запроса `multipart/form-data`, остальное — параметрами:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `file` | — | Файл схемы в кодировке UTF-8, не больше `schema.conversion.max-file-size-kb` |
| `type` | по расширению файла | Формат схемы: `sql` — SQL-скрипт, `xml` — журнал изменений Liquibase |
| `size` | `100` | Количество строк в каждом запросе на генерацию |
| `fileType` | `sql` | Формат файла в каждом запросе на генерацию: `csv`, `xlsx` или `sql` |

Пример ответа для таблицы `users (id BIGSERIAL PRIMARY KEY, email VARCHAR(255) NOT NULL UNIQUE, role_id INT REFERENCES roles (id))`:

```json
{
  "status": "SUCCESS",
  "requests": [
    {
      "tableName": "users",
      "size": 1000,
      "fileType": "sql",
      "columns": [
        {
          "name": "id",
          "type": "int",
          "generationStrategy": "algorithm",
          "config": { "notNull": true, "rangeType": "shift", "start": "1", "step": "1" }
        },
        {
          "name": "email",
          "type": "str",
          "generationStrategy": "algorithm",
          "config": { "unique": true, "notNull": true, "length": 16 }
        },
        {
          "name": "role_id",
          "type": "int",
          "generationStrategy": "algorithm",
          "config": { "rangeType": "random", "start": "1", "end": "1001" }
        }
      ]
    }
  ],
  "count": 1,
  "warnings": [
    "Table [users], column [role_id]: references [roles(id)], values are generated in range [1, 1000] in expectation of sequential ids of the referenced table"
  ]
}
```

- `requests` — запросы на генерацию, по одному на таблицу, в порядке создания таблиц в схеме. Каждый можно без изменений отправить в `POST /v1/generator`. Поля со значениями по умолчанию в них не выводятся.
- `warnings` — что в схеме учтено неточно или не учтено вовсе: неподдерживаемые типы, внешние и составные ключи, пропущенные колонки и таблицы.

Запросы — это заготовки. Схема говорит о типе колонки, но не о смысле данных, поэтому значения получаются подходящими по типу и ограничениям, но условными: случайные строки вместо имён и адресов, числа из диапазона по умолчанию. Перед генерацией колонкам стоит задать осмысленные диапазоны или заменить стратегию на `faker`, `dictionary` или `regexp`.

Примеры схем — в папке [samples/schemas](samples/README.md#схемы).

### Что читается из схемы

Основа описания таблицы — её создание. Кроме него учитываются изменения колонок и ключей таблиц, созданных в том же файле; всё остальное пропускается.

| Формат | Создание таблицы | Учитываемые изменения |
|---|---|---|
| SQL-скрипт | `CREATE TABLE` с колонками и ограничениями `NOT NULL`, `PRIMARY KEY`, `UNIQUE`, `REFERENCES`, `FOREIGN KEY` | `ALTER TABLE`: `ADD COLUMN`, `DROP COLUMN`, `ADD PRIMARY KEY`, `ADD UNIQUE`, `ADD FOREIGN KEY`, `ALTER COLUMN ... SET NOT NULL` и `DROP NOT NULL`; `CREATE UNIQUE INDEX`; `CREATE TYPE ... AS ENUM` |
| Журнал Liquibase (XML) | `createTable` с вложенными `column` и `constraints` | `addColumn`, `dropColumn`, `addPrimaryKey`, `addUniqueConstraint`, `addForeignKeyConstraint`, `addNotNullConstraint`, `dropNotNullConstraint`, `createIndex` с `unique="true"` |

SQL-скрипты разбираются в первую очередь по правилам PostgreSQL. Распространённые конструкции других СУБД тоже понимаются: имена в обратных апострофах и квадратных скобках, `AUTO_INCREMENT`, `IDENTITY`, `enum(...)` и определения индексов внутри `CREATE TABLE`. Комментарии, строковые литералы и тела функций в долларовых кавычках на разбор не влияют.

### Как подбираются параметры колонки

| Тип в схеме | Тип генератора | Параметры |
|---|---|---|
| `smallint`, `integer`, `bigint`, `serial`, `tinyint`, `numeric(p)` и другие целые | `int` | Случайные числа от 1 до 1 000 000 (для `smallint`, `tinyint` и `numeric(p)` — до предела типа) |
| `real`, `float`, `double precision` | `double` | Случайные числа от 0 до 1000 |
| `numeric(p, s)`, `decimal(p, s)`, `number(p, s)`, `money` | `decimal` | Случайные числа от 0 с `s` знаками после запятой, целая часть — не больше четырёх цифр |
| `boolean`, `bit`, `tinyint(1)` | `bool` | Случайные значения |
| `varchar(n)`, `char(n)`, `text`, `clob`, `bytea`, `blob` и другие строковые и двоичные | `str` | Случайная строка длиной `n`, но не больше 16 символов |
| `uuid`, `uniqueidentifier` | `uuid` | — |
| `date` | `date` | Случайные даты за последний год |
| `time` | `time` | Случайное время суток |
| `timestamp`, `datetime` | `datetime` | Случайные дата и время за последний год |
| `timestamp with time zone`, `timestamptz`, `datetimeoffset` | `zoned_datetime` | Случайные дата и время за последний год в UTC |
| `json`, `jsonb`, массивы (`text[]`) | `str`, стратегия `constant` | Константа `{}` — пустой объект JSON и пустой массив PostgreSQL. В ответе есть предупреждение |
| Перечисление: `CREATE TYPE ... AS ENUM`, `enum(...)` | `str`, стратегия `dictionary` | Словарь из значений перечисления |
| Остальные типы | `str` | Случайная строка из 16 символов. В ответе есть предупреждение |

Ограничения колонки меняют параметры так:

- `NOT NULL` и первичный ключ — `"notNull": true`. В колонке без `NOT NULL` примерно половина значений будет `null`.
- Первичный ключ, `UNIQUE` и уникальный индекс — для целых чисел последовательность с единицы (`"rangeType": "shift"`), для `decimal` последовательность с шагом в единицу младшего разряда, для остальных типов `"unique": true`. Логическим колонкам, перечислениям и константам уникальность не задаётся.
- `serial`, `IDENTITY`, `AUTO_INCREMENT`, `autoIncrement="true"` и значение по умолчанию `nextval(...)` — последовательность с единицы.
- Составной ключ — уникальной делается его первая колонка: генератор обеспечивает уникальность только в пределах одной колонки, а набор колонок уникален, если уникальна хотя бы одна из них. В ответе есть предупреждение.
- Внешний ключ целого типа — случайные числа от 1 до `size`. Расчёт на то, что таблица, на которую ссылается ключ, сгенерирована так же и с тем же `size`: тогда её идентификаторы — числа от 1 до `size`. Для ключей других типов целостность ссылок не обеспечивается. В обоих случаях в ответе есть предупреждение.
- `GENERATED ALWAYS AS IDENTITY` и вычисляемые колонки (`GENERATED ALWAYS AS (...)`) — колонка пропускается: её значение задаёт только база данных. В ответе есть предупреждение.

### Ограничения

- Операторы SQL-скрипта должны разделяться точкой с запятой.
- Файл рассматривается сам по себе: изменения таблиц, созданных в других миграциях, пропускаются, а подключаемые журналы Liquibase (`include`, `includeAll`) не читаются.
- Переименование таблиц и колонок, смена типа колонки и удаление таблиц не применяются.
- Условия `CHECK` и значения по умолчанию (`DEFAULT`) не учитываются: значение генерируется для каждой колонки.
- В журнале Liquibase не читаются изменения `sql` и `sqlFile`, а подстановки в типах (`type="${uuid.type}"`) не раскрываются — такая колонка генерируется строкой с предупреждением.
- Таблица без колонок в самом операторе (`CREATE TABLE ... AS SELECT`, `LIKE`) пропускается с предупреждением.

### Отключение конвертации

Настройка `schema.conversion.enabled=false` отключает метод: любой запрос к `POST /v1/schemas/convert` отклоняется с кодом `404`, остальные методы работают как прежде.

## Генерация через RabbitMQ

При `RABBITMQ_ENABLED=true` сервис принимает запросы на генерацию не только по HTTP, но и из очереди RabbitMQ. Обработка та же, что у `POST /v1/generator`: те же проверки, лимиты и форматы файлов.

Подключение к брокеру задаётся переменными окружения:

| Переменная окружения | По умолчанию | Назначение |
|---|---|---|
| `RABBITMQ_ENABLED` | `false` | Включить приём запросов из очереди |
| `RABBITMQ_HOST` | `localhost` | Адрес брокера |
| `RABBITMQ_PORT` | `5672` | Порт брокера |
| `RABBITMQ_USER` | `guest` | Имя пользователя |
| `RABBITMQ_PASS` | `guest` | Пароль |

Остальные параметры подключения и слушателя задаются стандартными свойствами Spring Boot `spring.rabbitmq.*`.

### Запрос

Запрос — сообщение в очереди `istochnik.generation.requests` (настройка `rabbitmq.generation.request-queue`). Тело сообщения — тот же JSON, что и у `POST /v1/generator`, в кодировке UTF-8. Сервис объявляет очередь сам при подключении к брокеру.

### Ответ

На каждый запрос сервис отправляет одно ответное сообщение:

- по адресу из свойства `reply-to` запроса, если оно задано;
- иначе — в очередь `istochnik.generation.responses` (настройка `rabbitmq.generation.response-queue`).

В ответ копируется `correlation-id` запроса, а если его нет — `message-id`. Результат определяется заголовком `status`:

| | Успех | Ошибка |
|---|---|---|
| Заголовок `status` | `SUCCESS` | `FAIL` |
| Тело сообщения | Сгенерированный файл | JSON с полями `status`, `code` и `message` — как в ответе с ошибкой по HTTP |
| `content-type` | `application/csv`, `application/xlsx` или `application/sql` | `application/json` |
| Заголовок `fileName` | Имя файла: `tableName` из запроса или `response`, с расширением формата | — |

Коды ошибок:

| `code` | Причина |
|---|---|
| `request.body.invalid.error` | Тело сообщения не разбирается как запрос на генерацию |
| `request.fields.invalid.error` | Ошибки в параметрах запроса. Поля `generalInfoErrors` и `columnErrors` содержат их описание, как в ответе `400` по HTTP |
| `generation.error` | Ошибка во время генерации колонки |
| `file.size.exceeded.error` | Файл больше `rabbitmq.generation.max-file-size-kb` |

Пример клиента на Spring AMQP, который отправляет запрос и ждёт ответ:

```java
Message request = MessageBuilder.withBody(json.getBytes(StandardCharsets.UTF_8))
        .setContentType(MessageProperties.CONTENT_TYPE_JSON)
        .build();

Message reply = rabbitTemplate.sendAndReceive("", "istochnik.generation.requests", request);
MessageProperties properties = reply.getMessageProperties();
if ("SUCCESS".equals(properties.getHeader("status"))) {
    Files.write(Path.of((String) properties.getHeader("fileName")), reply.getBody());
}
```

### Что нужно учитывать

- Запрос с ошибкой не возвращается в очередь: сервис отвечает сообщением со статусом `FAIL` и подтверждает запрос. Повторно доставляются только запросы, обработку которых прервал сбой самого сервиса или соединения.
- Файл передаётся одним сообщением, а брокер ограничивает его размер: в RabbitMQ 4 по умолчанию 16 МБ. Поэтому файл больше `rabbitmq.generation.max-file-size-kb` (по умолчанию 10 МБ) не отправляется — вместо него приходит ошибка. Если увеличиваете лимит, увеличьте и `max_message_size` брокера.
- Один экземпляр сервиса обрабатывает запросы из очереди по одному и не забирает следующий, пока не ответит на текущий. Число одновременно обрабатываемых запросов задаётся свойством `spring.rabbitmq.listener.simple.concurrency`.
- [Ограничение частоты запросов](#ограничение-частоты-запросов) на запросы из очереди не действует: нагрузку ограничивает число обработчиков.
- JWT в сообщениях не проверяется при любом значении `SECURITY_ENABLED`: доступ к очередям разграничивается учётными записями и правами брокера.
- Если брокер недоступен, сервис всё равно запускается, обслуживает HTTP-запросы и повторяет попытки подключения.
- Для ответов на запросы без `reply-to` нужен получатель: без него сообщения копятся в очереди ответов.

## Метрики

При `METRICS_ENABLED=true` сервис собирает метрики и отдаёт их в формате Prometheus по адресу `/actuator/prometheus`. При `METRICS_ENABLED=false` метрики не собираются, а адреса `/actuator/**` отвечают кодом `404`.

Метрики генерации:

| Метрика | Метки | Что показывает |
|---|---|---|
| `istochnik_generation_seconds_count`, `_sum`, `_max` | `file_type`, `outcome` | Количество и длительность генераций. `outcome` — `success` или `error` |
| `istochnik_generation_rows_total` | `file_type` | Количество сгенерированных строк в успешных генерациях |

Учитываются запросы и по HTTP, и из очереди RabbitMQ. Измеряется генерация значений колонок без формирования файла. Запрос, отклонённый проверкой параметров, до генерации не доходит и в эти метрики не попадает — по HTTP такие запросы видны в `http_server_requests_seconds_count` с меткой `status="400"`.

Кроме них доступны стандартные метрики Spring Boot: JVM (`jvm_*`), HTTP-запросы по методам и кодам ответа (`http_server_requests_seconds_*`), а при включённом RabbitMQ — соединения и каналы брокера (`rabbitmq_*`). У всех метрик есть метка `application="istochnik"`.

Пример настройки Prometheus:

```yaml
scrape_configs:
  - job_name: istochnik
    metrics_path: /actuator/prometheus
    static_configs:
      - targets: ["localhost:8103"]
```

Из адресов Actuator открыт только `prometheus`. Список задаётся стандартным свойством `management.endpoints.web.exposure.include`.

При `SECURITY_ENABLED=true` адрес `/actuator/prometheus` тоже требует JWT: в настройке Prometheus укажите получение токена в блоке `oauth2` или сам токен в блоке `authorization`.

## Ошибки

Ошибки в параметрах запроса возвращаются с кодом `400` и перечислены по колонкам:

```json
{
  "status": "FAIL",
  "code": "request.fields.invalid.error",
  "message": "Request fields have invalid states",
  "generalInfoErrors": "",
  "columnErrors": {
    "id": ["field [end] can't be less than field [start]"]
  }
}
```

Если пользователь превысил свой лимит запросов на генерацию, возвращается код `429` и заголовок `Retry-After`:

```json
{
  "status": "FAIL",
  "code": "rate.limit.exceeded.error",
  "message": "Too many generation requests from the user. Limit = [20] requests per [1] seconds"
}
```

Если ошибка возникла уже во время генерации колонки, а политика колонки — `INTERRUPT`, возвращается код `500`:

```json
{
  "status": "FAIL",
  "code": "generation.error",
  "message": "Error while generate column with name = [d]: field [step] must be greater than 0"
}
```

Если по схеме нельзя построить запросы на генерацию — не передан файл, неверный параметр, схема не разобрана или в ней нет таблиц, — метод конвертации возвращает код `400`:

```json
{
  "status": "FAIL",
  "code": "schema.conversion.error",
  "message": "Schema doesn't contain table definitions"
}
```

Если конвертация схем отключена настройкой, тот же метод возвращает код `404`:

```json
{
  "status": "FAIL",
  "code": "schema.conversion.disabled.error",
  "message": "Schema conversion is disabled by app settings"
}
```

## Безопасность

При `SECURITY_ENABLED=true` сервис работает как OAuth2 Resource Server: все запросы должны содержать действительный JWT, иначе возвращается `401`.

Для проверки токенов нужно указать поставщика одним из свойств Spring Boot (их можно передать переменными окружения):

| Свойство | Переменная окружения |
|---|---|
| `spring.security.oauth2.resourceserver.jwt.issuer-uri` | `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI` |
| `spring.security.oauth2.resourceserver.jwt.jwk-set-uri` | `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI` |

Без одного из них приложение с включённой безопасностью не стартует.

При `SECURITY_ENABLED=false` все методы доступны без аутентификации — используйте этот режим только для локальной разработки или в закрытом контуре.

Проверка JWT относится только к HTTP: и к методам API, и к адресу [метрик](#метрики) `/actuator/prometheus`. Запросы из [очереди RabbitMQ](#генерация-через-rabbitmq) токеном не защищены — ограничьте доступ к очередям учётными записями и правами брокера.

Выражения стратегии `expression` приходят в запросе и выполняются на сервере, поэтому язык ограничен: разрешены только литералы, ссылки на колонки, операторы и [функции из списка](#функции). Обращения к классам, конструкторам, бинам, методам и свойствам объектов отклоняются при проверке запроса и недоступны при вычислении. Если вычисляемые колонки не нужны, отключите стратегию настройкой `generation.expression.enabled=false`.

Регулярные выражения стратегии `regexp` тоже приходят от клиента, и по короткому выражению генератор может строить автомат очень долго или исчерпать память. Поэтому длина выражения, длина строк и сложность автомата проверяются до генерации, см. [Ограничения выражений](#ограничения-выражений).

Файл схемы для [конвертации](#конвертация-схем) тоже приходит от клиента. Он только разбирается: операторы SQL не выполняются, а в XML запрещены объявления `DOCTYPE` и внешние сущности, поэтому через схему нельзя прочитать файлы сервера или обратиться в сеть. Размер файла ограничен настройкой `schema.conversion.max-file-size-kb`. Если конвертация не нужна, отключите её настройкой `schema.conversion.enabled=false`.

## Разработка

Тесты:

```bash
./mvnw test
```

Большая часть тестов — API-тесты: они поднимают приложение на случайном порту с настройками из `src/test/resources/application.properties` и не требуют внешних сервисов.

Исключение — `GenerationOverRabbitMqTest`: он проверяет обмен сообщениями с настоящим RabbitMQ, который запускает в Docker через Testcontainers. Если Docker недоступен, тест пропускается.

Отчёт о покрытии (JaCoCo) формируется командой `./mvnw verify` в `target/site/jacoco/index.html`.

Форматирование кода (Spotless, Palantir Java Format):

```bash
./mvnw spotless:apply
```

### Структура проекта

| Пакет | Содержимое |
|---|---|
| `controllers` | REST-контроллеры, преобразование и проверка запросов |
| `listeners` | Приём запросов на генерацию из очереди RabbitMQ |
| `validators` | Проверка параметров колонок: по стратегии, базовому и пользовательскому типу |
| `services.handlers` | Обработчики стратегий генерации |
| `services.generators` | Генераторы значений базовых и пользовательских типов |
| `services.converters` | Конвертеры значений |
| `services.expression` | Разбор выражений стратегии `expression`, функции для них и порядок вычисления колонок |
| `services.file` | Формирование файлов CSV, XLSX и SQL |
| `services.schema` | Конвертация схем: разбор SQL-скриптов и журналов изменений Liquibase, подбор параметров генерации по типу колонки |
| `providers`, `config` | Реестры реализаций по типу и их сборка в Spring-контексте |
| `enums` | Типы, стратегии, конвертеры, топики, форматы файлов |

### Как добавить пользовательский тип

1. Добавить значение в `CustomType` и описание в `i18n/messages_*.properties`.
2. Написать генератор и его конфигурацию в `services.generators.custom`.
3. Добавить `ConfigMapperService`, который строит конфигурацию генератора из параметров запроса.
4. Добавить `CustomTypeGeneratorService` в `services.impl.generators.custom`.
5. При необходимости добавить `CustomTypeValidator` для проверки параметров.

Все реализации подхватываются автоматически: реестры в `ProvidersDelegateConfig` собирают их по типу.

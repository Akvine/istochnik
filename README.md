# Istochnik

Микросервис генерации тестовых табличных данных. По описанию колонок в JSON возвращает готовый файл в формате CSV, XLSX или SQL.

Сервис не хранит состояние и не использует базу данных: каждый запрос самодостаточен, а результат можно воспроизвести, передав `seed`.

## Возможности

- Пять стратегий генерации: константа, алгоритм, словарь, регулярное выражение, faker.
- Базовые типы (`int`, `double`, `str`, `bool`) и пользовательские: даты и время, UUID, точные десятичные числа, часовые пояса, российские реквизиты (СНИЛС, ИНН, КПП, ОГРН, ОГРНИП, ОКПО, БИК, расчётный счёт), IMEI, номера банковских карт («Мир», Visa, Mastercard).
- Случайные значения или последовательности с шагом, ограничения `unique` и `notNull`.
- Конвертеры — цепочка преобразований над сгенерированной колонкой (арифметика, работа со строками, форматирование дат, хеширование, сортировка).
- Выгрузка в CSV, XLSX и SQL (`INSERT` пачками).
- Воспроизводимая генерация по `seed`.
- Описания типов, стратегий и топиков на русском и английском языках.

## Требования

- JDK 21.
- Maven не нужен: в репозитории есть Maven Wrapper (`mvnw`, `mvnw.cmd`).
- Библиотека `ru.akvine:compozit-commons:1.0-SNAPSHOT` в локальном Maven-репозитории. Она содержит DTO запросов и общие утилиты. Установить её можно командой `mvn install` в репозитории `compozit-commons`.

## Сборка и запуск

Сборка (вместе с тестами):

```bash
./mvnw clean package
```

Готовый jar появится в `target/istochnik-0.0.1-SNAPSHOT.jar`.

У трёх настроек нет значений по умолчанию, без них приложение не стартует:

| Переменная окружения | Назначение |
|---|---|
| `SERVER_PORT` | Порт HTTP-сервера |
| `EUREKA_ENABLED` | Регистрация в Eureka: `true` или `false` |
| `SECURITY_ENABLED` | Проверка JWT на входящих запросах: `true` или `false` |

`EUREKA_URL` (адрес Eureka, например `http://localhost:8700/eureka/`) нужен только при `EUREKA_ENABLED=true`.

Запуск в bash:

```bash
SERVER_PORT=8103 EUREKA_ENABLED=false SECURITY_ENABLED=false java -jar target/istochnik-0.0.1-SNAPSHOT.jar
```

Запуск в PowerShell:

```powershell
$env:SERVER_PORT = "8103"; $env:EUREKA_ENABLED = "false"; $env:SECURITY_ENABLED = "false"
java -jar target\istochnik-0.0.1-SNAPSHOT.jar
```

Для локальной разработки удобно создать файл `src/main/resources/application-local.properties` со своими значениями и запускать приложение с профилем `local` (`--spring.profiles.active=local`). Файлы `application-*.properties` добавлены в `.gitignore`.

## Настройки

Задаются в `src/main/resources/application.properties` или любым способом, который поддерживает Spring Boot.

| Свойство | По умолчанию | Описание |
|---|---|---|
| `max.generation.rows.size` | `100000` | Максимальное число строк в одном запросе |
| `max.generation.columns.size` | `200` | Максимальное число колонок в одном запросе |
| `max.generation.attempts` | `100` | Сколько попыток в среднем на строку есть у случайного генератора, чтобы выполнить ограничения (`unique`, `valid`). При превышении генерация колонки завершается ошибкой |
| `max.dictionaries.per.column` | `10` | Максимальное число словарей в одной колонке |
| `max.dictionary.elements.count` | `10000` | Максимальное число элементов в одном словаре |
| `randomizer.seed` | пусто | Глобальный seed. Если задан, имеет приоритет над `seed` колонок: все запросы становятся детерминированными |
| `sql.insert.batch.size` | `1000` | Максимальное число строк в одном `INSERT`. Значение `0` или меньше отключает разбиение |
| `generation.rate.limiter.enabled` | `true` | Ограничивать частоту запросов на генерацию |
| `generation.rate.limiter.limit-for-period` | `20` | Сколько запросов на генерацию принимается за один период |
| `generation.rate.limiter.refresh-period-seconds` | `1` | Длительность периода в секундах |
| `parallel.executor.threads-count` | `100` | Размер пула потоков. Каждая колонка генерируется отдельной задачей |
| `parallel.executor.queue-capacity` | `1000` | Размер очереди задач пула |
| `log.total.generation.data.benchmark.enabled` | `false` | Писать в лог время генерации всего запроса |
| `log.column.generation.data.benchmark.enabled` | `false` | Писать в лог время генерации каждой колонки |

## API

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/v1/generator` | Сгенерировать файл |
| `GET` | `/v1/types/base` | Базовые типы |
| `GET` | `/v1/types/custom` | Пользовательские типы с базовым типом и примером значения |
| `GET` | `/v1/strategies` | Стратегии генерации и поддерживаемые ими ограничения |
| `GET` | `/v1/converters` | Конвертеры, доступные для каждого базового типа |
| `GET` | `/v1/topics` | Топики стратегии `faker` с примерами |

Справочные методы (кроме `/v1/converters`) принимают параметр `lang` — язык описаний: `en` (по умолчанию) или `ru`.

### Swagger

Описание всех методов с примерами запросов доступно в Swagger UI запущенного сервиса:

| Адрес | Что там |
|---|---|
| `/swagger-ui.html` | Swagger UI |
| `/v3/api-docs` | Спецификация OpenAPI в формате JSON |

Например, при запуске на порту 8103: `http://localhost:8103/swagger-ui.html`.

При `SECURITY_ENABLED=true` оба адреса, как и остальные методы, требуют JWT. Отключить их совсем можно стандартными свойствами springdoc: `springdoc.swagger-ui.enabled=false` и `springdoc.api-docs.enabled=false`.

### Ограничение частоты запросов

Метод `POST /v1/generator` защищён ограничителем частоты запросов: за период `generation.rate.limiter.refresh-period-seconds` принимается не больше `generation.rate.limiter.limit-for-period` запросов. Запрос сверх лимита сразу отклоняется с кодом `429`, заголовок `Retry-After` содержит время ожидания в секундах.

Лимит общий для всех клиентов и считается отдельно в каждом экземпляре приложения. На справочные методы он не распространяется.

## Запрос на генерацию

`POST /v1/generator`

Параметр строки запроса `tableName` задаёт имя возвращаемого файла (по умолчанию `response`).

Пример тела запроса:

```json
{
  "size": 3,
  "fileType": "sql",
  "tableName": "users",
  "columns": [
    {
      "name": "id",
      "type": "int",
      "generationStrategy": "algorithm",
      "config": { "rangeType": "shift", "start": "1", "step": "1" }
    },
    {
      "name": "full_name",
      "type": "str",
      "generationStrategy": "faker",
      "config": { "rangeType": "random", "notNull": true, "language": "ru", "topics": ["FULL_NAME"] }
    },
    {
      "name": "status",
      "type": "str",
      "generationStrategy": "dictionary",
      "config": { "rangeType": "random", "notNull": true, "dictionaries": [["NEW", "ACTIVE", "BLOCKED"]] }
    },
    {
      "name": "balance",
      "type": "decimal",
      "generationStrategy": "algorithm",
      "config": { "rangeType": "random", "notNull": true, "start": "0.00", "end": "10000.00" }
    },
    {
      "name": "created_at",
      "type": "datetime",
      "generationStrategy": "algorithm",
      "config": { "rangeType": "random", "notNull": true, "start": "2025-01-01 00:00:00", "end": "2025-12-31 23:59:59" },
      "converters": [{ "name": "format", "arguments": ["yyyy-MM-dd HH:mm:ss"] }]
    }
  ]
}
```

Вызов:

```bash
curl -X POST "http://localhost:8103/v1/generator?tableName=users_dump" -H "Content-Type: application/json" -d @request.json -o users_dump.sql
```

Ответ — файл `users_dump.sql`:

```sql
INSERT INTO users (ID, FULL_NAME, STATUS, BALANCE, CREATED_AT) VALUES
(1, 'Киселев Артём', 'ACTIVE', '6368.57', '2025-05-24 02:57:38'),
(2, 'Валентина Сергеевна Кудрявцева', 'BLOCKED', '622.51', '2025-02-16 14:22:46'),
(3, 'Константин Кулагин', 'NEW', '1462.85', '2025-09-27 22:59:18');
```

Больше готовых запросов — в папке [samples](samples/README.md): по одному на каждый тип, на каждую стратегию, на конвертеры и на таблицы целиком.

### Поля запроса

| Поле | Описание |
|---|---|
| `size` | Количество строк |
| `fileType` | Формат файла: `csv`, `xlsx` или `sql` |
| `tableName` | Имя таблицы в `INSERT`. Обязательно для `sql` |
| `columns` | Список колонок. Порядок колонок в файле совпадает с порядком в запросе |

### Поля колонки

| Поле | Описание |
|---|---|
| `name` | Имя колонки |
| `generationStrategy` | Стратегия: `constant`, `algorithm`, `dictionary`, `regexp`, `faker` |
| `type` | Тип данных. Используется только стратегией `algorithm`; для остальных стратегий укажите `str` |
| `config` | Параметры генерации (обязательный объект, см. ниже) |
| `converters` | Конвертеры, применяются к сгенерированным значениям по порядку |
| `convertToString`, `postConverters` | Если `convertToString=true`, значения нестрокового типа стратегии `algorithm` переводятся в строки, после чего к ним применяются строковые конвертеры из `postConverters` |
| `errorResolveInfo` | Что делать при ошибке генерации колонки: `{"policy": "INTERRUPT"}` — прервать запрос (по умолчанию), `{"policy": "IGNORE", "defaultValue": "..."}` — заполнить колонку значением `defaultValue` |

### Поля `config`

| Поле | Описание |
|---|---|
| `rangeType` | `random` — случайные значения, `shift` — последовательность с шагом |
| `start`, `end`, `step` | Границы диапазона и шаг. Передаются строками, формат зависит от типа |
| `notNull` | `true` — без `null`. При `false` примерно половина значений будет `null` |
| `unique` | `true` — значения не повторяются |
| `valid` | Для типов с контрольными разрядами: `true` — значения с корректной контрольной суммой |
| `length` | Длина строки для типа `str` |
| `constant` | Значение для стратегии `constant` |
| `dictionaries` | Словари для стратегии `dictionary` |
| `regexps` | Регулярные выражения для стратегии `regexp` |
| `topics`, `language` | Топики и язык для стратегии `faker` |
| `seed` | Seed колонки. Одинаковый seed при одинаковых параметрах даёт одинаковые значения |

## Стратегии генерации

| Стратегия | Что делает | Параметры `config` |
|---|---|---|
| `constant` | Заполняет колонку одним значением | `constant` |
| `algorithm` | Генерирует значения указанного типа | Зависят от типа, см. [Типы данных](#типы-данных) |
| `dictionary` | Выбирает значения из словарей. `random` — случайно, `shift` — по порядку по кругу. Одинаковые элементы разных словарей считаются одним значением | `dictionaries`, `rangeType`, `notNull`, `unique` |
| `regexp` | Генерирует строки, подходящие под регулярные выражения. `random` — выражение выбирается случайно, `shift` — по очереди. Поддерживается подмножество синтаксиса регулярных выражений (библиотека Xeger) | `regexps`, `rangeType`, `notNull` |
| `faker` | Генерирует правдоподобные данные по темам: имена, адреса, телефоны, email и другие. Полный список — в `GET /v1/topics` | `topics`, `language`, `rangeType`, `notNull` |

Строковые конвертеры доступны для стратегий `dictionary`, `regexp` и `faker`. Для `constant` конвертеры не применяются.

В регулярных выражениях стратегии `regexp` символы `@`, `#`, `&`, `~`, `<`, `>` и `"` имеют особое значение. Чтобы получить сам символ, экранируйте его обратной косой чертой: `[a-z]{5}\@example\.com` (в JSON — `"[a-z]{5}\\@example\\.com"`).

### Плюсы и минусы стратегий

| Стратегия | `unique` | `notNull` | Конвертеры | Проверка параметров до генерации | Значения в файле |
|---|---|---|---|---|---|
| `constant` | — | — | нет | нет | как в запросе: строка, число или логическое значение |
| `algorithm` | да | да | по базовому типу | да, для большинства типов | по базовому типу: числа, логические значения или строки |
| `dictionary` | да | да | строковые | да | строки |
| `regexp` | нет | да | строковые | нет | строки |
| `faker` | нет | да | строковые | нет | строки |

#### `constant`

Подходит для колонок с одним значением на всю таблицу: код валюты, признак, версия.

Плюсы:

- Самая простая и самая быстрая стратегия: нужно одно поле `constant`.
- Результат полностью предсказуем.
- Тип значения сохраняется: число остаётся числом и попадает в SQL без кавычек.

Минусы:

- Одно значение на всю колонку, `unique` и `notNull` не применяются.
- Конвертеры игнорируются.
- Поддерживаются только строки, числа и логические значения. Объект или массив в `constant` приводит к ошибке при выгрузке в SQL и XLSX.

#### `algorithm`

Подходит для идентификаторов, чисел, дат и реквизитов — всего, где важны диапазон, порядок или корректность контрольного разряда.

Плюсы:

- Самый широкий набор возможностей: 24 типа, включая даты с часовым поясом, точные десятичные числа, реквизиты и номера карт.
- Точное управление значениями: диапазон, шаг, последовательности, `unique`, `notNull`, корректные контрольные разряды через `valid`.
- Числа и логические значения остаются типизированными, для них доступны числовые конвертеры.
- Параметры большинства типов проверяются до генерации: ошибка возвращается с кодом `400` и описанием по каждой колонке.

Минусы:

- Только предусмотренные типы: произвольный формат строки так не получить.
- У каждого типа свои параметры и свой формат `start` и `end`, без таблицы типов не обойтись.
- Случайные значения распределены равномерно: нет ни правдоподобных имён и адресов, ни перекосов, характерных для реальных данных.
- `unique` для чисел и дат на больших объёмах работает медленно: 100 000 уникальных целых чисел генерируются десятки секунд вместо долей секунды.

#### `dictionary`

Подходит для справочных значений: статусы, категории, города, коды.

Плюсы:

- В колонке окажутся в точности те значения, которые нужны.
- Поддерживает `unique` и `notNull`, случайный выбор и обход по порядку.
- Нехватка значений для `unique` обнаруживается до генерации (код `400`).
- Одна из самых быстрых стратегий.

Минусы:

- Все значения нужно передать в запросе, и на них есть лимиты: по умолчанию 10 словарей по 10 000 элементов на колонку.
- Разнообразие ограничено размером словаря: уникальных строк не больше, чем элементов.
- Значения всегда строки: числа из словаря попадут в SQL в кавычках.
- Все значения равновероятны, задать веса нельзя.

#### `regexp`

Подходит для строк собственного формата, которого нет среди типов: номера заказов, артикулы, маски телефонов.

Плюсы:

- Любой формат строки без доработки сервиса.
- Несколько выражений в одной колонке: случайный выбор или чередование.
- Доступны строковые конвертеры.

Минусы:

- Нет `unique`: повторы возможны.
- Выражение не проверяется заранее: ошибка в синтаксисе обнаруживается только во время генерации и возвращается с кодом `500`.
- Синтаксис отличается от привычного. Классы `\d` и `\w` не работают — нужны `[0-9]` и `[a-z]`. Точка даёт произвольные символы Юникода. Часть символов служебные (см. выше).
- Квантификаторы без верхней границы (`*`, `+`) дают строки непредсказуемой длины — лучше указывать её явно: `{6}`, `{2,5}`.
- Не умеет считать контрольные разряды, и это одна из самых медленных стратегий.

#### `faker`

Подходит для правдоподобных, читаемых данных: ФИО, адреса, телефоны, email.

Плюсы:

- Данные выглядят как настоящие — удобно для демонстраций и ручного тестирования.
- Локализация через `language`: русские или английские имена и адреса.
- Несколько топиков в одной колонке, доступны строковые конвертеры.

Минусы:

- Нет `unique`: значения повторяются, особенно имена.
- Нет параметров диапазона, набор топиков фиксирован (список — в `GET /v1/topics`).
- Колонки не связаны между собой: имя в одной колонке и email в другой не соответствуют друг другу.
- Параметры не проверяются заранее: неизвестный топик приводит к ошибке `500` без пояснения.
- Составные топики (например, полный адрес) генерируются в несколько раз медленнее чисел и словарей.

По скорости стратегии различаются в разы: быстрее всех `constant` и `dictionary`, медленнее всех `regexp` и составные топики `faker`. Но и самые медленные генерируют колонку из 100 000 строк меньше чем за секунду, так что на практике скорость важна только для `unique` в `algorithm`.

## Типы данных

### Базовые типы

| Тип | Параметры | Примечания |
|---|---|---|
| `int` | `rangeType`, `start`; для `random` — `end`; для `shift` — `step`, `end` необязателен | Правая граница не включается |
| `double` | `rangeType`, `start`, `end`; для `shift` — `step` | Правая граница не включается |
| `str` | `length` | Случайная строка из латинских букв и цифр |
| `bool` | `rangeType`; для `shift` — `start` (`true` или `false`) | В режиме `shift` значения чередуются |

### Пользовательские типы

Каждый пользовательский тип основан на базовом: от него зависят доступные конвертеры и то, как значение попадает в файл (строкой или числом).

| Тип | Базовый | Формат `start` и `end` | Примечания |
|---|---|---|---|
| `uuid` | `str` | — | UUID версии 4 |
| `date` | `str` | `2025-12-25` | Шаг в режиме `shift` — в днях |
| `time` | `str` | `14:00:00` | Шаг в режиме `shift` — в секундах |
| `datetime` | `str` | `2025-12-25 10:30:00` | Шаг в режиме `shift` — в секундах. Значения выводятся в формате ISO-8601 (`2025-12-25T10:30:00`), другой формат задаётся конвертером `format` |
| `zoned_datetime` | `str` | `2025-12-25T10:30:00+03:00[Europe/Moscow]` или `2025-12-25 10:30:00 Europe/Moscow` | Часовой пояс значений берётся из `start`. Если в `start` указано только смещение (`+03:00`), название зоны в значениях не выводится. Шаг в режиме `shift` — в секундах (по умолчанию 1), `end` необязателен |
| `zone_id` | `str` | — | Идентификаторы часовых поясов (`Europe/Moscow`). По умолчанию выбираются случайно, при `rangeType: shift` — по алфавиту по кругу |
| `decimal` | `str` | `0.00` | Точные десятичные числа. Количество знаков после запятой берётся из `start`, `end` и `step`. Правая граница не включается. Для `shift` обязателен `step`, `end` необязателен |
| `snils` | `int` | — | СНИЛС |
| `inn_org` | `int` | — | ИНН организации (10 цифр) |
| `inn_pers` | `int` | — | ИНН физического лица (12 цифр) |
| `ogrn` | `int` | — | ОГРН (13 цифр) |
| `ogrnip` | `str` | — | ОГРНИП (15 цифр) |
| `okpo` | `str` | — | ОКПО организации (8 цифр) |
| `kpp` | `str` | — | КПП (9 цифр). Контрольного разряда нет |
| `bik` | `str` | — | БИК (9 цифр, начинается с 04). Контрольного разряда нет |
| `bank_account` | `str` | `start` — БИК банка, например `044525225` | Расчётный счёт в рублях (20 цифр). Контрольный ключ рассчитывается под БИК из `start` |
| `imei` | `str` | — | IMEI (15 цифр) |
| `card_mir` | `str` | — | Номер карты «Мир»: 16 цифр, начинается с 2200–2204 |
| `card_visa` | `str` | — | Номер карты Visa: 16 цифр, начинается с 4 |
| `card_mastercard` | `str` | — | Номер карты Mastercard: 16 цифр, начинается с 51–55 или 2221–2720 |

Для `zoned_datetime` и `decimal` поле `rangeType` обязательно. Для `date`, `time` и `datetime` обязательны `start` и `end`, а без `rangeType` используется режим `shift`.

Для `imei`, номеров карт, `ogrnip`, `okpo` и `bank_account` контрольный разряд рассчитывается только при `"valid": true`; без этого флага он случаен, и значение, как правило, не проходит проверку.

Контрольный ключ расчётного счёта зависит от БИК банка, поэтому при `"valid": true` для `bank_account` обязателен БИК в поле `start`. Все счета колонки генерируются под этот БИК. Чтобы в таблице был и сам БИК, добавьте колонку со стратегией `constant` и тем же значением — см. пример [samples/tables/organizations.json](samples/tables/organizations.json).

Для `snils`, `inn_org`, `inn_pers` и `ogrn` валидация требует поля `rangeType`, `start` и `end` (целые числа), хотя на результат они не влияют. Достаточно передать `"rangeType": "random", "start": "0", "end": "1"`.

## Конвертеры

Конвертер описывается объектом:

```json
{ "name": "multiply", "arguments": [1.5], "probability": 50 }
```

- `name` — имя конвертера;
- `arguments` — аргументы, если они нужны;
- `probability` — к какой доле строк (в процентах, от 1 до 100) применить конвертер. По умолчанию 100.

Какие конвертеры доступны, зависит от базового типа колонки.

### Для `int`

| Конвертер | Аргументы | Действие |
|---|---|---|
| `abs` | — | Модуль числа |
| `negative` | — | Смена знака |
| `plus`, `minus` | число | Сложение, вычитание |
| `multiply` | число | Умножение. Дробная часть результата отбрасывается |
| `divide` | число, не 0 | Деление. Дробная часть результата отбрасывается |
| `mod` | число | Остаток от деления |
| `pow` | число | Возведение в степень |
| `factorial` | — | Факториал |

### Для `double`

| Конвертер | Аргументы | Действие |
|---|---|---|
| `abs`, `negative` | — | Модуль числа, смена знака |
| `plus`, `minus`, `multiply` | число | Сложение, вычитание, умножение |
| `divide` | число, не 0 | Деление |
| `pow` | число | Возведение в степень |
| `round` | количество знаков | Округление |
| `ceil`, `floor` | — | Округление вверх, вниз |
| `sin`, `cos`, `tan`, `cot`, `arcsin`, `arccos`, `arctan` | — | Тригонометрические функции |
| `exp` | — | Экспонента |
| `log`, `log10` | число, не 0 (обязателен, в вычислении не участвует) | Натуральный и десятичный логарифм |
| `zscore` | — | Стандартизация значений колонки |
| `minMaxScaling` | — | Приведение значений колонки к диапазону от 0 до 1 |

### Для `str`

| Конвертер | Аргументы | Действие |
|---|---|---|
| `upperCase`, `lowerCase` | — | Верхний, нижний регистр |
| `capitalize` | — | Первая буква в верхнем регистре |
| `inversion` | — | Смена регистра каждой буквы на противоположный |
| `randomCase` | — | Случайная смена регистра букв |
| `trim` | — | Удаление пробелов по краям |
| `removeWhitespaces` | — | Удаление пробельных символов |
| `reverse` | — | Строка в обратном порядке |
| `addBefore`, `addAfter` | текст | Добавление текста в начало, в конец |
| `repeat` | количество (по умолчанию 1) | Повтор строки |
| `substring` | начальный и конечный индексы | Подстрока |
| `replaceAll` | регулярное выражение, замена | Замена по регулярному выражению |
| `format` | шаблон, например `dd.MM.yyyy HH:mm:ss` | Форматирование значений `date`, `datetime` и `zoned_datetime` |
| `translit` | — | Транслитерация кириллицы |
| `base64` | — | Кодирование в Base64 |
| `md5` | — | Хеш MD5 в шестнадцатеричном виде |
| `randomNumericReplace` | — | Замена цифр случайными цифрами |
| `randomEnglishReplace`, `randomRussianReplace` | — | Замена латинских или кириллических букв случайными буквами того же алфавита |
| `randomReplace` | — | Замена каждого символа случайной буквой, цифрой или спецсимволом |

### Общие (для `int`, `double` и `str`)

| Конвертер | Действие |
|---|---|
| `shuffle` | Перемешивание значений колонки |
| `sort_asc`, `sort_desc` | Сортировка по возрастанию, по убыванию |
| `to_null` | Замена значений на `null` с вероятностью `probability` |

Для `bool` конвертеров нет.

## Форматы файлов

- **CSV** — разделитель `;`, первая строка содержит имена колонок, `null` записывается пустым значением.
- **XLSX** — один лист `sheet`, первая строка содержит имена колонок.
- **SQL** — операторы `INSERT INTO ... VALUES`, не более `sql.insert.batch.size` строк в каждом. Имена колонок переводятся в верхний регистр. Строки заключаются в одинарные кавычки, числа и логические значения пишутся без кавычек, `null` — как `NULL`. Имена таблицы и колонок подставляются как есть, без экранирования, поэтому передавайте только проверенные значения.

## Ошибки

Ошибки в параметрах запроса возвращаются с кодом `400` и перечислены по колонкам:

```json
{
  "status": "FAIL",
  "code": "request.fields.invalid.error",
  "message": "Request fields have invalid states",
  "generalInfoErrors": "",
  "columnErrors": {
    "id": ["field [end] can't be less than field [start]"]
  }
}
```

Если превышен лимит запросов на генерацию, возвращается код `429` и заголовок `Retry-After`:

```json
{
  "status": "FAIL",
  "code": "rate.limit.exceeded.error",
  "message": "Too many generation requests. Limit = [20] requests per [1] seconds"
}
```

Если ошибка возникла уже во время генерации колонки, а политика колонки — `INTERRUPT`, возвращается код `500`:

```json
{
  "status": "FAIL",
  "code": "generation.error",
  "message": "Error while generate column with name = [d]: field [step] must be greater than 0"
}
```

## Безопасность

При `SECURITY_ENABLED=true` сервис работает как OAuth2 Resource Server: все запросы должны содержать действительный JWT, иначе возвращается `401`.

Для проверки токенов нужно указать поставщика одним из свойств Spring Boot (их можно передать переменными окружения):

| Свойство | Переменная окружения |
|---|---|
| `spring.security.oauth2.resourceserver.jwt.issuer-uri` | `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI` |
| `spring.security.oauth2.resourceserver.jwt.jwk-set-uri` | `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI` |

Без одного из них приложение с включённой безопасностью не стартует.

При `SECURITY_ENABLED=false` все методы доступны без аутентификации — используйте этот режим только для локальной разработки или в закрытом контуре.

## Разработка

Тесты:

```bash
./mvnw test
```

Большая часть тестов — API-тесты: они поднимают приложение на случайном порту с настройками из `src/test/resources/application.properties` и не требуют внешних сервисов.

Отчёт о покрытии (JaCoCo) формируется командой `./mvnw verify` в `target/site/jacoco/index.html`.

Форматирование кода (Spotless, Palantir Java Format):

```bash
./mvnw spotless:apply
```

### Структура проекта

| Пакет | Содержимое |
|---|---|
| `controllers` | REST-контроллеры, преобразование и проверка запросов |
| `validators` | Проверка параметров колонок: по стратегии, базовому и пользовательскому типу |
| `services.handlers` | Обработчики стратегий генерации |

### Как добавить пользовательский тип

1. Добавить значение в `CustomType` и описание в `i18n/messages_*.properties`.
2. Написать генератор и его конфигурацию в `services.generators.custom`.
3. Добавить `ConfigMapperService`, который строит конфигурацию генератора из параметров запроса.
4. Добавить `CustomTypeGeneratorService` в `services.impl.generators.custom`.
5. При необходимости добавить `CustomTypeValidator` для проверки параметров.

Все реализации подхватываются автоматически: реестры в `ProvidersDelegateConfig` собирают их по типу.
